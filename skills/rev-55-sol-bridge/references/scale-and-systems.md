# Scale and System Lane Cards

Read this only after evidence selects an artifact, visual/game, mass-corpus, executable-farm, or local-service lane.

## Scale Gate

Before executing more than 100 similar targets:

1. Sample distant IDs and time representative runs.
2. Separate stable container/operand grammar from per-instance values or opcode maps.
3. Recover the native contract from one or two samples only.
4. Normalize to a compact extractor/interpreter before the batch.
5. Preserve ordered manifests, checkpoints, raw lengths, and hashes.

The first batch goal is not full recovery. It is two coherent adjacent chunks or two distant samples that prove the assumed contract generalizes.

## Artifact, Stage, or Overlay

**First artifact:** an extracted blob with original offset, length, magic, and hash.

**Route:**

1. Inspect sections, resources, appended data, filesystem boundaries, archives, and self-reading code before loader/UI analysis.
2. Validate candidates by magic/header/container metadata and parse them with the native format tool.
3. Once a verified stage2 exists, stop analyzing stage1 except for the loader/decrypt contract.
4. For digest-only live gates, search offline constructors, dead-code helpers, overlays, journals, relocation maps, and encrypted gate blocks before preimage work.
5. Preserve the raw artifact before trimming, repair, decompression, color conversion, or OCR.

**Pivot:** a visible token or magic string without verifier/parser support is a decoy candidate, not a solve.

## Game, Simulation, or Visual Signal

**First artifact:** a compact state table: map/coordinates, win predicate, RNG/tick state, object placement, frame states, or server validation boundary.

**Route:**

1. Ignore renderer/engine boilerplate unless it controls success.
2. Convert continuous or visual state into a grid, graph, bitmask, glyph sequence, or low-dimensional tuple.
3. For Unity, inspect serialized scenes, `GameObject`, `Transform`, names, sprites, and textures; placement may encode a second channel.
4. For deterministic simulation, mirror update order, width/precision, clamping, constants, and iteration count before solving residuals.
5. For visual tokens, preserve raw frames, collapse duplicate states, segment glyphs, and obtain an independent reading.

**Pivot:** noisy visuals mean switch to state arrays, serialized assets, or server predicate. Do not keep playing/rendering manually.

## Mass VM or Opcode-Permutation Corpus

**First artifact:** operand grammar plus per-instance semantic evidence from at least two distant VMs.

**Route:**

1. Inventory numeric IDs, missing entries, worker/program pairs, and expected aggregate size.
2. Trace program-buffer reads in one VM to recover instruction boundaries, state layout, input/output, and verifier tail.
3. Infer semantics from structural idioms; never reuse one raw opcode map when bytes are permuted.
4. Normalize each instance to one canonical ISA and run only the reached subset in a compact interpreter.
5. Recover the first two chunks early and require coherent header continuity before scaling.
6. Reassemble strictly by numeric ID and hash the untouched stream.

**Verification:** representative original VMs accept, raw length matches the contract, container checks pass, and any visual answer has an independent reading.

## Executable or Library Farm

**First artifact:** controller order, worker ABI, buffer sizes, and one validated worker-family model.

**Route:**

1. Recover the controller contract before individual workers.
2. Sample distant workers and cluster by behavior/structural anchors.
3. Extract constants only after cross-sample confirmation.
4. Model each family as a compact reversible operation and invert the controller chain in reverse order.
5. Preserve worker hashes and duplicate order. Avoid launching a large unknown corpus when static extraction suffices.

**Pivot:** repeated manual worker analysis means the classifier is missing; build the family map first.

## Local Service or Firmware Composition

**First artifact:** a boundary table covering parser, auth/session, database/backend, crypto/config, and response renderer.

**Route:**

1. Run supplied services loopback-only unless the challenge explicitly requires its authorized remote.
2. Label missing remote values with unmistakable local sentinels; never report a sentinel as an event flag.
3. Turn observable differences into an exact oracle and distinguish lookup, authentication, handler reachability, and leakage.
4. Label crypto objects by semantic role and call order, not proximity in memory/decompilation.
5. Verify each reachable stage separately, then the full local chain.

**Pivot:** similar error pages are not distinct oracle states without stable evidence. Missing external state is a blocker, not a reason to fabricate completion.
